## Überblick

MCP, das Model Context Protocol, gibt KI-Assistenten direkten Zugriff auf die Brainz-Wissensbasis. Der Brainz MCP-Server in Version 3.0.0 stellt 47 Tools, 3 Resources und 2 Prompts bereit, mit denen LLMs Inhalte suchen, erstellen, verknüpfen und analysieren können, ohne dass Sie eigene API-Aufrufe verdrahten müssen.

Der Server unterstützt lokale Nutzung über `stdio` und Remote-Anbindung über HTTP. Für lokale Clients wie Claude Desktop oder Claude Code ist `stdio` der Standard. Für gehostete Integrationen ist Streamable HTTP über `POST /mcp` der empfohlene Transport.

## Transport-Modi

Wählen Sie den Transport danach aus, wo Ihr MCP-Client läuft. Lokal ist `stdio` am einfachsten, remote ist HTTP der bevorzugte Weg.

<Tabs>
  <Tab title="stdio (Standard)" icon="terminal">

  Für lokale Nutzung mit Claude Desktop oder Claude Code verwendet Brainz Kommunikation über `stdin` und `stdout`.

  - Für lokale Nutzung mit Claude Desktop und Claude Code
  - Kommunikation über `stdin` und `stdout`
  - Start mit `node server/mcp.mjs` oder `npm run mcp`
  - Empfohlen für Einzelplatz-Nutzung

  ```bash
  node server/mcp.mjs
  ```

  </Tab>
  <Tab title="HTTP (Empfohlen für Remote)" icon="cloud">

  Für entfernte MCP-Clients stellt Brainz Streamable HTTP über einen einzigen Endpoint bereit.

  - Einheitlicher Endpoint: `POST /mcp`
  - Session-Management über den Header `Mcp-Session-Id`
  - Standard-Port: `3001`, konfigurierbar über `MCP_PORT`
  - Sessions mit `DELETE /mcp` schließen
  - Health-Check über `GET /health`

  Wenn Brainz als Hauptanwendung läuft, ist MCP HTTP auf dem App-Port unter `/mcp` verfügbar.

  </Tab>
  <Tab title="SSE (Legacy)" icon="arrow-right">

  SSE bleibt für ältere MCP-Clients verfügbar, wird aber durch den HTTP-Transport ersetzt.

  - Server-Sent Events für ältere MCP-Clients
  - Verbindungsaufbau über `GET /sse`
  - Nachrichten über `POST /messages?sessionId=...`
  - Nur für Legacy-Integrationen sinnvoll

  </Tab>
</Tabs>

## Resources (3)

Resources geben einem MCP-Client strukturierte Hintergrundinformationen über das Brainz-System. Sie eignen sich besonders für Agenten, die Schema- oder Auth-Wissen vor einem Tool-Aufruf laden sollen.

| Resource | URI | Inhalt |
| --- | --- | --- |
| `tables` | `schema://tables` | Tabellendefinitionen mit Spalten, Typen, Indizes und RLS-Policies |
| `functions` | `schema://functions` | Alle SQL-Funktionen mit Signaturen |
| `auth-system` | `schema://auth` | Auth-System mit Rollen, JWT und dem Zusammenspiel mit RLS |

## Authentifizierung

Der MCP-Server kann auf drei Arten einen Benutzerkontext setzen. Welche Methode sinnvoll ist, hängt davon ab, ob Sie lokal, automatisiert oder über HTTP arbeiten.

- **`MCP_USER_ID`** — Direkt-Authentifizierung ohne Login, sinnvoll für automatisierte Setups
- **`BRAINZ_USER` und `BRAINZ_PASS`** — Auto-Login beim Start, vor allem für `stdio`
- **`login`** — manueller Login als erster Tool-Aufruf

Für HTTP-Transporte können Sie zusätzlich einen Server-Token absichern. Setzen Sie dafür `MCP_AUTH_TOKEN` auf dem Server und senden Sie im Client einen `Authorization`-Header mit Bearer-Token.

<Callout kind="info">

Alle Datenbankzugriffe laufen unter Row Level Security. Der MCP-Server sieht nur die Daten des authentifizierten Benutzers, weil alle Abfragen über den RLS-Kontext ausgeführt werden.

</Callout>

## Claude Desktop Konfiguration

Mit `stdio` binden Sie Brainz direkt in Claude Desktop ein. Der häufigste Aufbau verwendet `node` als Command und übergibt Datenbank- und Login-Umgebungsvariablen in der Konfiguration.

<Steps>
  <Step title="Config-Datei öffnen" icon="edit">

  Öffnen Sie die Claude-Desktop-Konfigurationsdatei. Auf macOS liegt sie unter `~/Library/Application Support/Claude/claude_desktop_config.json`.

  </Step>
  <Step title="Brainz-Server eintragen" icon="code">

  Tragen Sie den Brainz MCP-Server in `mcpServers` ein.

  ```json
  {
    "mcpServers": {
      "brainz": {
        "command": "node",
        "args": ["/path/to/brainz/server/mcp.mjs"],
        "env": {
          "DATABASE_URL": "postgres://user:password@localhost:5432/brainz",
          "BRAINZ_USER": "your@email.com",
          "BRAINZ_PASS": "your-password"
        }
      }
    }
  }
  ```

  Wenn Claude Desktop die Konfiguration akzeptiert, erscheint der Server nach dem Neustart in der MCP-Liste des Clients.

  </Step>
  <Step title="Claude Desktop neu starten" icon="play-circle">

  Starten Sie Claude Desktop vollständig neu, damit die MCP-Konfiguration neu geladen wird.

  </Step>
  <Step title="Verbindung testen" icon="check-circle">

  Testen Sie die Verbindung mit einer einfachen inhaltlichen Frage, zum Beispiel: `Was sind meine letzten Inhalte?`

  Wenn die Verbindung funktioniert, kann Claude Brainz-Tools aufrufen und auf Ihre Inhalte zugreifen.

  </Step>
</Steps>

Für einen gehosteten Server reicht in der Regel eine URL-basierte Konfiguration aus.

```json
{
  "mcpServers": {
    "brainz": {
      "url": "https://your-domain.com/mcp"
    }
  }
}
```

## Konfiguration

Die wichtigsten Umgebungsvariabablen steuern Transport, Authentifizierung und URL-Verhalten des MCP-Servers.

<ParamField body="MCP_TRANSPORT" param-type="string" required="false" show-location="false">

Transport-Modus. Gültige Werte sind `stdio`, `sse` und `http`. Standard ist `stdio`.

</ParamField>

<ParamField body="MCP_PORT" param-type="integer" required="false" show-location="false">

Port für SSE- und HTTP-Transporte. Standard ist `3001`.

</ParamField>

<ParamField body="MCP_USER_ID" param-type="integer" required="false" show-location="false">

Setzt den Benutzerkontext direkt, ohne vorherigen Login-Aufruf.

</ParamField>

<ParamField body="MCP_AUTH_TOKEN" param-type="string" required="false" show-location="false">

Bearer-Token für HTTP-Authentifizierung. Wenn gesetzt, muss der Client einen passenden `Authorization`-Header mitsenden.

</ParamField>

<ParamField body="BRAINZ_USER" param-type="string" required="false" show-location="false">

E-Mail-Adresse für Auto-Login beim Start des MCP-Servers.

</ParamField>

<ParamField body="BRAINZ_PASS" param-type="string" required="false" show-location="false">

Passwort für Auto-Login beim Start des MCP-Servers.

</ParamField>

<ParamField body="DATABASE_URL" param-type="string" required="true" show-location="false">

PostgreSQL-Verbindungszeichenfolge für Brainz.

</ParamField>

<ParamField body="BASE_URL" param-type="string" required="false" show-location="false">

Öffentliche Basis-URL für generierte Links. Standard ist `http://localhost:3000`.

</ParamField>
