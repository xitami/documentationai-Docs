## Überblick

Mit dieser Anleitung bringen Sie Brainz von null auf eine lokal laufende Instanz. Docker Compose startet PostgreSQL 16 mit `pgvector` und `pg_cron`, Redis und den App-Container in einem gemeinsamen Setup.

<Callout kind="info">

**Voraussetzungen**

- Docker und Docker Compose v2+
- Git
- Mindestens 4 GB RAM
- Optional: Node.js 20+ für Bare-Metal-Entwicklung ohne Docker

</Callout>

## Installation

<Steps>
  <Step title="Repository klonen" icon="github" title-type="p">

```bash
git clone https://github.com/xitami/PostgresBackend.git
cd PostgresBackend
```

  </Step>

  <Step title="Environment konfigurieren" icon="settings" title-type="p">

```bash
cp .env.example .env
```

Die wichtigsten Variablen, die Sie setzen müssen:

- `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` — Datenbank-Credentials
- `JWT_SECRET` — Mindestens 32 Zeichen
- `PORT` — Standard: `3000`

Generieren Sie ein geeignetes Secret zum Beispiel so:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

<Callout kind="alert">

Verwenden Sie in Produktion immer ein kryptographisch sicheres Secret. Teilen Sie es niemals öffentlich.

</Callout>

  </Step>

  <Step title="Docker Compose starten" icon="play-circle" title-type="p">

```bash
docker compose up --build -d
```

Der Befehl startet drei Services: PostgreSQL 16 mit `pgvector` und `pg_cron`, Redis 7 und die Brainz-App. Beim ersten Start spielt PostgreSQL die SQL-Dateien aus `./sql/` automatisch ein.

  </Step>

  <Step title="Migrationen ausführen" icon="database" title-type="p">

Führen Sie für nachfolgende Schema-Updates diesen Befehl aus:

```bash
docker exec postgresbackend-app-1 node scripts/migrate.js
```

Das Migrations-System verwaltet mehr als 265 SQL-Dateien und verfolgt den Status in `public.schema_migrations`.

  </Step>

  <Step title="Zugriff verifizieren" icon="check-circle" title-type="p">

Brainz läuft unter `http://localhost:3000`. Die GraphQL-API erreichen Sie unter `http://localhost:3000/graphql`.

Wenn alles korrekt gestartet ist, antwortet der Server auf eingehende Requests und die GraphQL-Route ist erreichbar.

  </Step>
</Steps>

<Callout kind="tip">

Tipp: Testen Sie die API mit einer einfachen GraphQL-Query:

```graphql
query {
  currentUser {
    id
    username
  }
}
```

</Callout>

## Entwicklung ohne Docker

Wenn Sie Brainz ohne Container entwickeln, richten Sie die Laufzeitdienste lokal ein und starten die App direkt mit Node.js.

<Steps>
  <Step title="Node.js installieren" icon="package" title-type="p">

Installieren Sie Node.js 20 oder neuer, damit die lokalen Skripte und der Entwicklungsserver zuverlässig laufen.

  </Step>

  <Step title="PostgreSQL vorbereiten" icon="database" title-type="p">

Richten Sie PostgreSQL 16 ein und aktivieren Sie die Extensions `pgvector` und `pgcrypto`.

  </Step>

  <Step title="Redis starten" icon="server" title-type="p">

Starten Sie einen lokalen Redis-Server, bevor Sie die App ausführen.

  </Step>

  <Step title="Abhängigkeiten installieren" icon="download" title-type="p">

```bash
npm install
```

  </Step>

  <Step title="Migrationen ausführen" icon="database" title-type="p">

```bash
node scripts/migrate.js
```

  </Step>

  <Step title="Entwicklungsserver starten" icon="terminal" title-type="p">

```bash
npm run dev
```

Der Entwicklungsmodus startet mit `--watch` und lädt Änderungen automatisch neu.

  </Step>
</Steps>

## Häufige Probleme

- **Port 3000 belegt**: Setzen Sie `PORT=3001` in `.env`.
- **Docker hat zu wenig Speicher**: Weisen Sie in Docker Desktop unter Settings → Resources mindestens 4 GB RAM zu.
- **Migrations-Fehler**: Führen Sie `docker compose down -v` aus und starten Sie das Setup neu, um einen frischen Datenbankzustand zu erhalten.
